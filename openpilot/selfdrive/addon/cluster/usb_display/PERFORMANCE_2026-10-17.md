# USB H.264 기기 로그 확인

대상은 `26-10-17-15_37_Unknown_UnregisteredDevice_cluster_debug.log`와
`26-10-17-15_47_Unknown_UnregisteredDevice_cluster_debug.log`입니다.
아래 수치는 시작 구간을 포함한 각 10초 통계 행의 산술 평균입니다.

| 항목 | 15_37 로그 | 15_47 로그 |
| --- | --- | --- |
| USB 제출 FPS 평균 | 13.56 | 13.34 |
| USB 제출 FPS 범위 | 11.62~14.47 | 11.49~13.87 |
| 제출 통계 표본 수 | 13 | 14 |
| RGB→NV12 변환 평균 | 55.85ms | 57.99ms |
| 변환 통계 표본 수 | 14 | 15 |
| heartbeat에서 관측한 전송 실패 | 0 | 0 |
| 모니터가 보고한 큐 깊이 | 0 | 0 |

사용자가 USB에서도 부드러운 출력을 확인했습니다. 로그에는 하드웨어 인코더 오류나
Python crash 기록이 없고, 지속적인 USB 전송 큐 적체도 보이지 않습니다.
다만 `submitted_fps`는 USB 전송 완료 횟수이며 모니터의 실제 표시 FPS가 아닙니다.

목표 20FPS의 프레임 간격은 50ms입니다. 현재 직렬 RGB→NV12 변환만 평균 약56~58ms를
사용하므로 이 경로가 목표 속도를 제한합니다. 합성·변환·하드웨어 출력 준비·USB 전송은
겹쳐 실행되며, `prepare_avg`에는 비동기 출력 대기도 포함되므로 이를 순수 하드웨어
인코딩 시간으로 해석하거나 단계 시간을 단순 합산하지 않습니다.

차량·모델 입력이 관측되지 않은 구간이므로 이 두 로그만으로 실제 주행 시 modeld나
locationd에 미치는 영향을 판단할 수 없습니다. 이후 검증에서는 변환 시간과 제출 FPS에
더해 `[CLUSTER_INPUT_DIAG]`, `[CLUSTER_RESOURCE_PERF]`, 부하 보호 기록을 함께 확인합니다.

이번 변경은 USB·Network H.264 실행 경로를 정리하고 코덱 선택을 제거합니다.
USB의 변환 알고리즘이나 하드웨어 인코딩 설정을 바꾸지는 않았으므로 위 수치는
변경 전 기준이며, 변경 후 기기 출력과 주행 성능은 새 로그로 확인합니다.
